Microelectronics.NMOS — Function

NMOS(name, drain, gate, source, body=source; model="ald1105n", W, L, M, ...) NMOS(; name, drain, gate, source, body=source, model="ald1105n", W, L, M, ...)

An n-channel MOSFET. The body is tied to the source unless given, and the model defaults to the ALD1105 n-channel device in the model library, whose default size is W = 20 μm, L = 10 μm.

Instance parameters are keywords, with or without units: W and L (channel size), M (number of devices in parallel), and AD, AS, PD, PS, NRD, NRS. Without a name, the next free name (M1, M2, ...) is used.

Examples

julia> NMOS("M1", "d", "g", 0)                     # body tied to the source
M1    d     g     0     0     ald1105n

julia> NMOS("M2", "d", "g", "s", 0; model="CD4007N", W=60u"μm", L=10u"μm")
M2    d     g     s     0     CD4007N W=6e-05 L=1e-05

Return a String declaring a SPICE instance of a two-terminal bipole device of the specified species, connected between nodes nplus and nminus, with an automatically assigned device name. Microelectronics.device_values — Method

device_values(name)

Operating values of MOSFET name in the latest operating-point, DC or transient analysis, with units:

  • id: current into the drain
  • vgs, vds, vbs: terminal voltages
  • vth: threshold voltage, including the body effect
  • vdsat: drain-source saturation voltage (vgs - vth for level-1 models)
  • gm, gds, gmbs: transconductance, output conductance, body transconductance
  • region: :cutoff, :triode or :saturation

Voltages and currents follow the circuit's sign convention, so for a PMOS vgs, vds, vth and id are normally negative. After an operating-point analysis each value is a single number; after a DC sweep or transient analysis each is a vector.

Example

julia> build_netlist(; sources=[Vdc("VDD","d",0,5u"V"), Vdc("VG","g",0,3u"V")],
                       components=[NMOS("M1","d","g",0)]);

julia> simulate(:op); device_values("M1")
(id = 0.001363 A, vgs = 3.0 V, vds = 5.0 V, vbs = 0.0 V, vth = 0.7 V, vdsat = 2.3 V,
 gm = 0.001185 S, gds = 3.45e-5 S, gmbs = 0.000... S, region = :saturation)

Microelectronics.independent_source — Method

independent_source(species;args...)

Instantiate an independent Voltage or Current source. species is "V" or "I".

Keyword arguments

All instances must have the positive and negative terminals assigned via nplus and nminus.

Optionally, a name can be given.

Remaining keyword arguments are specific to the desired source species.

  • DC source:
    • dc specifies the desired voltage or current
  • AC source:
    • ac specifies the AC magnitude (usually 1)
  • SIN source:
    • offset
    • amplitude
    • frequency
    • phase
  • PWL source:
    • points
  • PULSE source
    • high
    • low
    • width
    • period

If no keyword arguments are given, a zero-value source is instantiated.

Microelectronics.opamp — Method

opamp(;name,nplus,nminus,out,model="ideal_opamp",params="")

Instantiate a three-terminal op amp subcircuit. There are no positional arguments. Mandataory keyword arguments are:

  • name – 'X' is prefixed
  • nplus – non-inverting input terminal
  • nminus – inverting input terminal
  • out – output terminal

Optional keyword arguments:

  • model – name of subcircuit model (ideal_opamp is default)
  • params – a string with additional subcircuit parameters

The model must be the name of a three-terminal op amp subcircuit that has been defined or included in the netlist. Any params are specific to the model, but may include things like the power rails, slew rate, current limit, etc.

Example

julia> opamp(;name="OA1", nplus=0, nminus=2, out=3, model="my_opamp")

Microelectronics.pwl_string — Method

pwl_string(points::Vector{Tuple{Number,Number}})

Returns a SPICE-formatted string for a Piecewise Linear independent source using data provided in points. Each element of points is a Tuple indicating (time,value). The time and value can be Unitful Quantities or unitless numbers, in which case they are assumed to be (s,V) or (s,A) depending on the source species. Generally speaking, the points should be ascending in time. It is not necessary to use the same units for each point.

Examples

julia> points=Vector{Tuple{Number,Number}}()
julia> push!(points,(0,0))
julia> push!(points,(1u"ms",2u"mV"))
julia> pwl_string(points)
"PWL ( 0 0 0.001 0.02)"
